# Shira Coach: ניהול ומעקב אימונים אישיים

אפליקציית Web בעברית, מותאמת לנייד (PWA), לניהול מתאמנים, תכנון אימונים, תיעוד בזמן אמת, מעקב התקדמות והמלצות מנומקות.
נבנתה לפי מסמך האפיון. העיקרון: תכנון מראש ← תיעוד מהיר ← סיכום אוטומטי ← המלצות מנומקות ← אישור המאמנת.

## החלטות טכניות (תשובות לסעיף 17 באפיון)

| שאלה | ההחלטה | למה |
|---|---|---|
| Web, אפליקציה מקורית או שילוב? | **PWA**: אתר שמותקן למסך הבית בטלפון ועובד גם במחשב | מתקינים אותו מהדפדפן, בלי חנות אפליקציות. מתעדכן לבד, ונפתח כמו אפליקציה. |
| בסיס נתונים | **IndexedDB במכשיר** (דרך Dexie), במודל local-first | כל פעולה נשמרת מיד במכשיר. אין שרת, אין עלות, והמידע הרפואי לא יוצא מהמכשיר. |
| מצב לא מקוון מלא, או רק טיוטות? | **מצב לא מקוון מלא** | האפליקציה נטענת ועובדת בלי קליטה בכלל (Service Worker). אימון פעיל נשמר בכל לחיצה, וטפסים לא שמורים (מתאמן, תוכנית) נשמרים כטיוטה ומשוחזרים. |
| מאמנת אחת או כמה? | **מאמנת אחת, עם מבנה נתונים שמוכן להתרחבות** | לכל רשומה יש מזהה ייחודי (UUID), חותמות זמן ומחיקה רכה. כך אפשר להוסיף בהמשך סנכרון ענן ומשתמשים מרובים בלי לשכתב. |
| יומן, תשלומים, תקשורת | **לא נכללו** | לפי ההמלצה באפיון: קודם מסכי האימון. |
| חישוב נפח עקיף | ראו [חישוב נפח](#חישוב-נפח-שבועי) | הכללים שקופים וניתנים לעריכה, וכל מספר מוצג עם הפירוט שלו. |
| ייצוא, גיבוי ושחזור | ראו [גיבוי](#גיבוי-ושחזור-5-שכבות) | יש חמש שכבות הגנה, כך שתקלה אחת לא יכולה למחוק את המידע. |

## גיבוי ושחזור (5 שכבות)

1. **קובץ גיבוי מלא (JSON)**: בכפתור ״גיבוי עכשיו״. בטלפון הקובץ נשלח ישירות לדרייב, לוואטסאפ או למייל, ובמחשב הוא יורד כקובץ. הקובץ כולל חתימת שלמות, כך שקובץ פגום או ערוך מזוהה ונחסם.
2. **שחזור מקובץ** בשני מצבים:
   - **מיזוג** (מומלץ): מוסיף רשומות חסרות, ומעדכן רשומה רק אם הגרסה בקובץ חדשה יותר. שום דבר לא נמחק. מתאים גם להעברת נתונים בין טלפון למחשב.
   - **החלפה מלאה**: הנתונים יהיו בדיוק כמו בקובץ.
3. **נקודות שחזור אוטומטיות בתוך האפליקציה ("מכונת זמן")**: נשמרת נקודה אחת ביום, לפני כל שחזור, ייבוא, מחיקת מתאמן/ת או מחיקת אימון, ובלחיצה על "שמירה עכשיו". הנקודות דחוסות ונשמרות עד 20: 12 הנקודות היומיות האחרונות ו-5 השמירות הידניות האחרונות מוגנות, ונקודות "לפני פעולה" ישנות נמחקות ראשונות. אפשר לחזור לכל נקודה או להוריד אותה כקובץ.
4. **גיבוי אוטומטי לתיקייה במחשב** (Chrome או Edge): בוחרים פעם אחת תיקייה, רצוי בתוך OneDrive או Google Drive, והאפליקציה כותבת אליה קובץ יומי בכל פתיחה ובסוף כל אימון. נשמרים 30 הימים האחרונים.
5. **ייצוא לאקסל (CSV)**: יומן סטים, מתאמנים ומדידות. הקבצים קריאים גם בלי האפליקציה.

בנוסף, האפליקציה מבקשת מהדפדפן **אחסון קבוע** (כדי שלא ימחק נתונים), ומציגה **תזכורת** אם לא נשמר גיבוי מחוץ למכשיר במשך X ימים (ברירת מחדל: 7).

> חשוב: הנתונים נשמרים בדפדפן שבו עובדים. טלפון ומחשב הם שני מאגרים נפרדים. מעבירים ביניהם בגיבוי ושחזור במצב **מיזוג**.

## חישוב נפח שבועי

- כל **סט עבודה שהושלם** נספר כ־**סט ישיר אחד** לכל שריר **עיקרי** של התרגיל.
- אותו סט נספר גם לשרירים **המשניים**, כפול **מקדם עקיף**:
  - המקדם של התרגיל עצמו, אם הוגדר (נערך בספריית התרגילים, לכל תרגיל ושריר).
  - אחרת, מקדם ברירת המחדל מההגדרות (0.5).
- **נפח אפקטיבי = ישיר + Σ(עקיף × מקדם)**. הוא מושווה ליעד האישי של המתאמן/ת (טווח מינימום עד מקסימום לכל שריר).
- סטי חימום לא נספרים. סטי דרופ נספרים, ואפשר לבטל את זה בהגדרות. אפשר גם לספור רק סטים "קשים" (RIR ≤ 3 או 4).
- **תדירות**: מספר האימונים בשבוע שבהם השריר קיבל לפחות סט ישיר אחד.
- **חפיפה**: האפליקציה מתריעה כששריר קיבל עבודה משמעותית ביומיים רצופים.
- לחיצה על שורה של שריר מציגה בדיוק אילו תרגילים תרמו לו, כמה סטים, ובאיזה מקדם.
- יעדי ברירת מחדל לפי רמה: שימור (4–8), מתחיל (6–10), בינוני (10–16), מתקדם (12–20). לשרירים קטנים היעד נמוך יותר. אפשר לקבוע יעד לכל שריר בכרטיס המתאמן, ויעד 0 פירושו "לא נמדד".

## מנוע ההמלצות

המנוע מבוסס חוקים שקופים ולא משנה שום דבר לבד. כל המלצה מציגה מה זוהה, על אילו נתונים היא מבוססת ומה אפשר לעשות. לכל המלצה יש סטטוס: ממתינה, אושרה, נערכה, נדחתה או בוצעה. אישור של המלצה משנה את התוכנית ויוצר **גרסה חדשה** עם הסיבה.

| חוק | מתי |
|---|---|
| העלאת משקל | כל סטי העבודה הושלמו בראש הטווח, ה-RIR תקין והטכניקה טובה. הקפיצה לפי הציוד. קפיצה כפולה מוצעת רק אחרי שני אימונים רצופים מעל הטווח. |
| הוספת חזרות | ה-RIR גבוה מהיעד ב-2 או יותר, ויש עוד מקום בתוך טווח החזרות. |
| הפחתת עומס | רוב הסטים מתחת לטווח **בשני אימונים רצופים**. אימון בודד לא מספיק. |
| התאמת טווח | הטווח לא מתאים למטרת התוכנית, או תרגיל משקל גוף שהגיע לראש הטווח. |
| החלפת תרגיל | כאב ב-2 מתוך 3 האימונים האחרונים, קושי טכני מתמשך, או אין התקדמות במשך N שבועות (ניתן להגדרה). |
| בדיקת התאוששות | ירידה בשני אימונים רצופים בשני תרגילים או יותר, אנרגיה או שינה נמוכות, או מאמץ גבוה ברצף. |
| בקרת תוכנית | נפח מתחת ליעד או מעליו בשבוע שעבר, או ביצוע של פחות מ-75% מהסטים המתוכננים. |
| **בטיחות** | כאב מדווח, או טכניקה "לא מספקת" או "נדרש תיקון", **חוסמים** כל המלצה להעלאת עומס. המלצות פתוחות להעלאה מבוטלות אוטומטית. |

## שימוש מקומי במחשב

```bash
npm install
npm run dev        # פיתוח: http://localhost:4590
npm test           # בדיקות יחידה (חישובי נפח, מנוע, גיבוי, הפרדת תכנון/ביצוע)
npm run build      # בנייה לתיקיית dist
```

ב-Windows אפשר גם ללחוץ פעמיים על `START.bat`. הקובץ בונה את האפליקציה ופותח אותה בכתובת http://localhost:4591 (גרסת הבנייה, עם מצב לא מקוון). הנתונים בדפדפן נשמרים לפי כתובת, כך שגרסת הפיתוח (4590) והגרסה הבנויה (4591) הן שני מאגרים נפרדים.

## פרסום לטלפון (GitHub Pages)

כדי להתקין בטלפון, האפליקציה צריכה כתובת HTTPS. הקובץ `.github/workflows/deploy.yml` בונה, בודק ומפרסם אותה אוטומטית ל-GitHub Pages בכל דחיפה ל-`main`.
הקוד מתפרסם, אבל **הנתונים לא**: הם נשארים רק במכשיר של המשתמשת.
אחרי הפרסום: פותחים את הכתובת בטלפון, ובוחרים בתפריט הדפדפן ״הוספה למסך הבית״.

### באייפון
1. לפתוח את הכתובת **בספארי**, ללחוץ על כפתור השיתוף ואז על ״הוספה למסך הבית״.
2. לפתוח את האייקון החדש **פעם אחת כשיש אינטרנט**. מאז האפליקציה עובדת גם בלי קליטה.
3. לעבוד **רק מהאייקון**. לאפליקציה שבמסך הבית יש אחסון משלה, נפרד מספארי. מה שהוזן בספארי לא מופיע בה, וספארי עלול למחוק אותו אחרי שבוע בלי כניסה. האפליקציה מציגה את האזהרה הזו כל עוד היא פתוחה בספארי.
4. במסך **גיבוי**: לבדוק שמופיע ״אחסון קבוע״, ולשלוח גיבוי ראשון (״שמירה בקבצים״ או לדרייב).
5. מחיקת האייקון ממסך הבית מוחקת את כל הנתונים. לכן לפני מחיקה או החלפת טלפון צריך לגבות לקובץ, ובטלפון החדש לבחור: גיבוי ← בחירת קובץ גיבוי.

עוד דברים שכדאי לדעת באייפון:
- צליל סוף המנוחה לא נשמע כשהטלפון במצב שקט, ואין רטט. במקרה כזה רק פס הזמן מסמן את סוף המנוחה.
- עד iOS 18.4, אפליקציה במסך הבית לא יכלה למנוע נעילת מסך. בגרסה ישנה יותר האפליקציה מציעה לעדכן או להאריך את הנעילה האוטומטית.

## מבנה הקוד

```
src/
  domain/      לוגיקה טהורה: טיפוסים, נפח, מנוע המלצות, התקדמות, סיכום, השוואת גרסאות
  db/          מסד הנתונים (Dexie), כתיבה מרוכזת (repo), גיבוי ושחזור, hooks חיים
  data/        ספריית 129 תרגילים עם מיפוי שרירים ומקדמים
  components/  רכיבי ממשק משותפים, גרפים, פאנל נפח, כרטיס המלצה, טיימר מנוחה
  pages/       המסכים
```

## בהמשך (לא בגרסה הזו)

- **סנכרון ענן** (למשל Supabase): מאפשר מכשירים מרובים והתחברות. מודל הנתונים כבר מתאים: מזהים ייחודיים, `updatedAt`, מחיקה רכה ומיזוג לפי עדכניות.
- פורטל מתאמנים, יומן ותשלומים: רק אחרי שמסכי האימון יוכיחו את עצמם, לפי האפיון.
